# Scoring rubric

Generated from `scoring/src/main/resources/rubric.json` (version 1) by `tools/render_rubric.py`. **Do not edit this file by hand** — edit the JSON and re-run the script. The risk engine loads the same file, so the numbers below are the numbers actually used.

## Bands

| Band | Score |
|---|---|
| Low | 0-29 |
| Medium | 30-59 |
| High | 60-79 |
| Critical | 80-100 |

## How a score is built

```
score = min(sum of permission categories, permission_subtotal_cap)
      + min(sum of special access,        special_access_cap)
      + provenance modifiers
      + static manifest findings
      + threat-intelligence modifier
      + combination-rule bonuses
      + context-mismatch bonus
      then x system-app dampening, clamped to 0..100
```

The **permission subtotal cap of 45** is the most important number here. Ordinary permissions, however many an app holds, cannot by themselves push it past Medium. Reaching High or Critical requires special access, a combination rule, poor provenance, a context mismatch or a threat-intelligence hit. Without that cap a legitimate messaging app outscores a torch app holding an accessibility service, and the ranking stops answering "which app can do the most harm?".

Other ceilings: special access 60, network category 5 (network is low risk alone and earns its weight through combinations).

## Reducers

| Reducer | Multiplier |
|---|---:|
| Verified security/MDM tool holding device admin | x0.20 |
| Verified accessibility tool | x0.20 |
| Category explained by a device role (default SMS app, dialer...) | x0.25 |
| System or updated-system app (whole score) | x0.55 |

A reducer applies only on **verified** trust: a matching package name alone never qualifies, because package names are trivially spoofable. Trust requires a pinned signing certificate or arrival from Google Play or an OEM store.

## Threat intelligence

- Malicious verdict: **+40** and a band floor of **critical**
- Suspicious verdict: **+15**

Lookups send a SHA-256 fingerprint and nothing else, only after explicit, revocable, default-off consent.

## Context mismatch

| Severity | Bonus | Band floor |
|---|---:|---|
| Critical | +20 | critical |
| High | +14 | high |
| Medium | +8 | - |
| Low | +4 | - |
| Info | +0 | - |

Only the single worst mismatch scores. Several mismatches on one app describe the same underlying oddity, and adding them up would count one observation repeatedly.

## Explanations

Every High or Critical app carries at least **3 plain-language reasons**, ranked by contribution. Reasons are emitted by the scoring rules themselves, never written in a second pass, so the number and the words cannot drift apart. Padding, when needed, only ever promotes things that are true about that app; nothing is invented.
